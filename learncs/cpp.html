C++ from memory upward.

Focus on the parts of C++ that matter when you care about representation, ownership, lifetime, and how software maps onto a machine.

ObjectsMemoryReferencesRAIIContainersPerformance

1. Start with representation

A variable is not just a name. It has a type, a size, a lifetime, and some location in memory. C++ exposes enough of that model to make data layout part of program design.

Value

The object itself. Copying a value normally creates another object with its own state.

Reference

An alias for an existing object. A reference does not create a second copy of that object.

Pointer

A value that stores an address. It can be reassigned and can also be null.

Lifetime

The interval during which an object exists and may be used legally.

int value = 42;
int& reference = value;
int* pointer = &value;

reference += 1;   // changes value
*pointer += 1;    // also changes value

2. Stack, dynamic storage, and ownership

Automatic objects are destroyed when their scope ends. Dynamically allocated objects outlive the expression that created them and need an ownership strategy.

void automatic_storage() {
    Widget w;            // destroyed at end of scope
}

auto p = std::make_unique<Widget>();
// p owns the Widget.
// destruction follows p automatically.

Modern C++ usually expresses ownership with RAII types such as std::unique_ptr, containers, file streams, locks, and other objects whose destructors release resources.

Exercise: write a small type that prints from its constructor and destructor. Create it in nested scopes and predict the destruction order before running it.

3. Copies are a design decision

Passing a large object by value can create a copy. Passing by const reference gives read-only access to the existing object.

void inspect(const std::vector<int>& values) {
    // no vector copy
}

void consume(std::vector<int> values) {
    // owns its parameter copy/move
}

The right choice depends on intent. Do not mechanically replace every value parameter with a reference.

4. Containers are data-structure choices

std::vector

Contiguous memory, fast iteration and indexing, amortized append. Usually the default sequence.

std::unordered_map

Hash-based key lookup. Strong when repeated exact-key access matters.

std::map

Ordered tree structure. Keeps keys sorted and gives logarithmic operations.

std::array

Fixed-size contiguous storage with value semantics.

5. Checkpoint

  • Explain the difference between an object, a reference, and a pointer without using the word “basically.”
  • Explain why RAII prevents entire classes of cleanup bugs.
  • Know when copying is intentional versus accidental.
  • Choose a container from workload requirements, not familiarity.
  • Be able to reason about object lifetime across nested scopes.
