LEARNCS / DATA STRUCTURES

Choose from the workload backward.

A data structure is a set of tradeoffs. Start with the operations your program performs, then choose the representation that makes those operations cheap enough.

ArraysListsHash tablesTreesHeapsGraphs

1. Cost model

Access

How quickly can I reach an element by position or key?

Insert / remove

What work is required to change membership?

Order

Does the structure preserve sequence or sorted order?

Memory locality

Are elements close together in memory, helping caches and traversal?

2. Array vs linked list

An array/vector gives constant-time indexing and excellent locality. A linked list gives direct node insertion/removal once you already have the node, but finding a position is linear and pointer chasing is unfriendly to caches.

vector:  [A][B][C][D]        contiguous

list:    [A] -> [B] -> [C]   separate nodes

Big-O does not capture every cost. Two O(n) traversals can behave very differently on real hardware because memory access matters.

3. Hash table vs sorted representation

This is the same tradeoff explored in Data Workbench. If you need many exact-key lookups, paying once to build an index can dominate repeated scanning.

Linear scan

O(qn)

No preprocessing. Useful for tiny data or very few queries.

Hash index

O(n + q) average

Build once; repeated exact-key lookups are cheap.

Sort + binary search

O(n log n + q log n)

Useful when sorted order is already valuable or maintained.

Tree

O(log n) operations

Maintains ordering incrementally rather than sorting a full copy each time.

Exercise: for 23,000 records, explain why sorting the whole dataset can lose to a linear scan when the query count is small enough.

4. Heap and priority queue

A binary heap is optimized around repeatedly accessing the minimum or maximum element. It is not a general sorted container.

          2
        /   \
       5     7
      / \   /
     9  12 10

Typical operations: inspect top in O(1), insert in O(log n), remove top in O(log n).

5. Checkpoint

  • Explain why a vector can outperform a linked list even when both operations are O(n).
  • Know when preprocessing changes the total cost of a workload.
  • Distinguish a hash table from an ordered tree by what each preserves.
  • Explain why a heap is not a fully sorted array.
  • Include memory behavior when comparing data structures.
